## Addendum (same day): bulk import, synthetic agents, real-browser proof

Requested after the Phase 1 hand-off: "a simple config that generates 1000 websites without
any effort, each a new website with a new config for a new agent", double-checked in a browser.

### What was added

- **CSV import (§12, A5)** — `platform:site:import <file> [--dry-run|--resume=<id>|--batch=100]`
  and `platform:import:status`. One live site per row through `ProvisionTenant` (the single
  write path), batches of 100 as chained queue jobs, checkpoint per row in the new `import_runs`
  table (migration 022), bad rows in `<file>.errors.csv` (a new run starts a fresh file, a
  resume appends), idempotent re-runs (`existing_rows`).
- **Synthetic agents** — `platform:site:generate --count=N --seed=S [--provision] [--draft]`
  writes a CSV of N different agents (Arabic-script, Arab-Latin and international names,
  agencies, licences, areas, palette, dark mode, default locale, languages, Instagram, years)
  and, with `--provision`, imports it. Same seed → same CSV (`Random\Randomizer`, Xoshiro256**).
- **`platform:site:list [--random] [--limit] [--json]`**, `ThemeRegistry::installed()`,
  `AccountResolver` (shared by create/import), CI job `e2e`.
- **Playwright** (`npm run e2e`): `tests/E2E/prepare.sh` seeds a fresh `platform_e2e` database
  with `E2E_SITES` generated sites (1000 locally, 200 in CI) plus one draft, then Chromium on a
  375×667 mobile viewport opens sites **by host** (`--host-resolver-rules` maps
  `*.example.test` to the local server).

### What the browser verified (12 randomly sampled sites + platform checks)

Each sampled site opens on its own `{slug}.example.test` host; an en-GB browser lands on `/en`
(`lang=en`, `dir=ltr`) and `/ar` renders the same agent right-to-left; the `<h1>` is that
agent's name; a tappable `wa.me/971…` link and the sticky WhatsApp bar are visible; the tenant
palette reaches the DOM (`--c-primary`); no horizontal scroll at 375 px; a browser preferring
a language the site does not offer is redirected to the site's own default locale. The data set
itself is checked for variety (unique slugs, hundreds of distinct names, ≥ 6 palettes, both
default locales). Listings and a listing page work and demo listings carry no structured data.
A draft is a 404 without its preview token and renders with it. An unknown host is a 404. The
landing page serves the ar/en headline on the apex host. Screenshots land in
`tests/E2E/screenshots/` (CI uploads them as an artifact).

### Decisions

`docs/DECISIONS.md` #31–34 (per-row checkpoints + chained batch jobs, uninstalled themes are
errors, seeded generator, Playwright by host on `php artisan serve`).

### Gaps

- The queue is `sync` in tests and locally; under Horizon the batches run in the background and
  `platform:import:status` is how progress is followed — that path gets its first real run at
  bootstrap, like everything Redis-backed.
- Generated copy is template text (Phase 2 swaps in the Claude generator for exactly those
  fields); generated agents have no photo, so the hero shows the initial avatar.
