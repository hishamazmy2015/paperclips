# Phase 2 report — 2026-09-26 (Onboarding)

## 1. Status

**Built and tested: the whole §13 flow from the landing page to a live site, plus auth, AI
content, the funnel and reminders.** A new agent signs in without a password (Google, an emailed
code with a magic link, or a WhatsApp code), gets a draft site the moment the account exists,
fills three phone-sized screens (about you → your website → go live) with autosave, watches the
real draft in an iframe, publishes, and lands on a success screen with the URL, a QR code and a
WhatsApp share. Playwright drives that exact flow on a 375×667 Chromium; the timed runs are in §4.

Phase 0's server steps are still pending (§7), so A2's "on a real phone" half is still to be run
on `app.{base}` once the stack is up — the code path is the same one Playwright exercises.

## 2. What was built

- **Sign-in (§13 S1, §6, §17)** — `app/Auth`: `OtpService` (6 digits, 10 min, 5 attempts, keyed
  hashes, per-identifier and per-IP limits), `SignIn` (finds or creates account + owner user +
  draft site, trial 14 days, audit + `account.created` event), `Turnstile` (off until keyed, fails
  closed), Socialite Google; controllers for `/start`, email code, WhatsApp code, the shared code
  screen (auto-submit at six digits, Arabic-Indic digits accepted), the signed magic link, Google,
  logout; `AppLocale` middleware (`?lang=`, session, account locale, Accept-Language).
- **Provisioning changes (§12)** — `ProvisionInput::partial` (a draft may lack the WhatsApp
  number), `PublishTenant::missingForPublish` + `CannotPublish` (a site never goes live without a
  name and a valid number), `ProvisionTenant::refreshTemplateContent` (template copy follows the
  facts as the agent types), `scheduleAiContent`, `TenantLifecycle::changeDraftSlug` (the host row
  follows a draft's slug; published slugs still only move through rename + redirect).
- **Wizard (§13 S2–S4)** — one Livewire component (`app/Livewire/Onboarding/Wizard`) with
  `?step=` in the URL: name, WhatsApp validated live, agency autocomplete (seeded UAE brokerages,
  free text allowed), licence, photo (camera capture, square WebP 512); subdomain prefilled with a
  300 ms availability check and three suggestions, theme cards rendered with the agent's own
  name/photo/palette (marina and palm shown as "coming soon" until Phase 3), six palette swatches
  and "From my logo" (dominant colour → custom palette); area chips; the real draft site in an
  iframe (the app host is the only allowed ancestor); Publish / Finish later; progress bar, ar/en
  toggle, RTL; resume at the last step reached.
- **Success (§13 S5)** — confetti, tap-to-copy URL, QR (SVG), Share on WhatsApp, Open my site,
  checklist with % (listings, domain, testimonials, Instagram, logo); `share.clicked{channel}`.
  A minimal `/home` page ("Finish later" lands there; the dashboard is Phase 4).
- **Providers (§6)** — `ClaudeGenerator` on the official `anthropic-ai/sdk` (`claude-opus-5`,
  structured JSON per field × locale, server-side refusal fallback, queued only),
  `Dialog360Notifier`, `FileNotifier` and a `file` mail transport (sinks for dev/staging/E2E),
  Postmark wiring, `config/providers.php`, `.env.example` keys.
- **Media (§17)** — GD re-encoding to WebP, `media` disk, `MediaController` on the tenant host
  (own directory only) and the app host (owner only), immutable caching.
- **Funnel + reminders (§13)** — events for every step, `platform:funnel` (starts, sign-ups,
  per-step views/completions/drop-off/median seconds, published; by device and locale),
  `SendOnboardingReminders` every 15 min (+1 h, +24 h; email + WhatsApp when verified; signed
  opt-out), migration 023.
- **Landing (§13 S0)** — CTA to `app.{base}/start`, three theme previews, live counter.
- **Docs** — `docs/ONBOARDING.md`, DECISIONS #35–44, README, `.env.example`.

## 5. Risks and known gaps

- **Real-phone run pending.** Playwright at 375×667 is the automated proxy for A2; the median
  below is server + browser time without a human typing. The first run on a phone against the
  deployed stack (Phase 0 blockers) is what closes A2 formally.
- **Third-party cookies in the preview iframe.** The iframe loads the draft with the preview
  token in the URL on every load, so it needs no cookie; links inside the preview are not meant
  to be followed (sandboxed).
- **Claude, 360dialog, Postmark, Google and Turnstile have not been exercised against the real
  services** (no keys in this environment); each is behind an interface with a tested fallback,
  and the provider classes are unit-tested against faked HTTP.
- **Queue is `sync` locally**; the reminders job and `GenerateContent` get their first Horizon run
  at bootstrap.
- **Themes marina and palm are visible but disabled** in the picker until Phase 3 ships them.

## 6. Blockers (unchanged)

1. **Server access** — `make discover`, `make pre-platform-backup`, then `infra/scripts/bootstrap.sh`.
2. **DNS on Cloudflare + API token** (wildcard certificate).
3. **Approve D1–D5, create the private repository, set the CI variable `PLATFORM_BASE_DOMAIN`.**
4. New for Phase 2, needed before the real-phone run: **Google OAuth client, Postmark token (+
   sending domain), 360dialog key + sender, Turnstile keys, Anthropic key** — all listed as
   `[KEY NEEDED]` in `.env.example`; every flow works without them through the fallbacks.
